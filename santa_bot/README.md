# Тайный Санта — Telegram-бот

Бот по сценарию `@ssanta_bot`: открывает регистрацию при добавлении в группу,
принимает по одному пожеланию от участника и по `/end` проводит жеребьёвку,
рассылая каждому в личку `@username` получателя и его пожелание.

Стек: Python 3.12, aiogram 3, SQLite (aiosqlite), один процесс с long polling.

## Запуск

```bash
cd santa_bot
pip install -r requirements.txt
BOT_TOKEN=123456:ABC python -m santa_bot
```

Docker:

```bash
docker build -t santa-bot santa_bot
docker run -d -e BOT_TOKEN=123456:ABC -v santa-data:/app/data santa-bot
```

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `BOT_TOKEN` | — | токен от @BotFather |
| `DATABASE_PATH` | `santa.db` | файл SQLite |
| `REQUIRE_GROUP_MEMBERSHIP` | `1` | регистрироваться могут только члены группы (ссылку можно переслать) |

В @BotFather режим приватности можно не отключать: команды бот получает и так.
Если в группе несколько ботов, пишите команду с упоминанием: `/end@имя_бота`.

## Команды

| Где | Команда | Кто | Что делает |
|---|---|---|---|
| группа | `/stat` | все | число и список `@username` участников; после жеребьёвки — статус доставки |
| группа | `/end` | организатор | жеребьёвка и рассылка |
| группа | `/retry` | организатор | повторная рассылка тем, кому не доставлено |
| личка | `/start santa_<token>` | все | регистрация (открывается кнопкой «Участвовать») |
| личка | `/wish <текст>` | участник | сохранить/заменить пожелание |
| везде | `/info`, `/help` | все | инструкция и список команд |

Организатор — тот, кто добавил бота в группу. Если он хочет играть, он тоже
регистрируется по ссылке.

## Как устроено

- `santa_bot/handlers.py` — обработчики aiogram.
- `santa_bot/db.py` — схема и все операции с БД. Каждая изменяющая операция
  выполняется в транзакции `BEGIN IMMEDIATE`, поэтому проверка статуса игры и
  запись атомарны: двойной `/end` создаёт один набор пар, а регистрация или
  `/wish` во время жеребьёвки получают «регистрация закрыта».
- `santa_bot/draw.py` — жеребьёвка: `random.SystemRandom().shuffle()` и цикл
  «каждый дарит следующему, последний — первому».
- `santa_bot/delivery.py` — рассылка после коммита жеребьёвки. Статус каждой
  пары: `pending` → `sent` / `failed`. Рассылки одной игры идут
  последовательно (lock на игру), ошибка у одного участника не мешает
  остальным.

Ограничения в БД: `UNIQUE(game_id, telegram_user_id)` и
`UNIQUE(game_id, username_normalized)` в `participants`;
`UNIQUE(game_id, giver_id)`, `UNIQUE(game_id, receiver_id)` и
`CHECK(giver_id <> receiver_id)` в `assignments`; в группе может быть только
одна открытая игра (частичный уникальный индекс).

### Поведение в спорных случаях

- **Повторное добавление бота** в группу с открытой игрой снова публикует
  ссылку той же игры. Если прошлая игра уже разыграна, создаётся новая.
- **Без `@username`** зарегистрироваться нельзя — бот подсказывает, где его
  задать, и даёт кнопку, чтобы открыть ссылку снова.
- **Конфликт username.** Если имя занято участником с устаревшими данными, бот
  сначала проверяет его текущий username через Telegram и обновляет запись
  сам. Если не получилось, новый участник получает просьбу повторить позже, а
  владелец устаревшей записи — просьбу заново открыть ссылку.
- **Перед `/end`** бот сверяет `@username` всех участников с Telegram. Сменившие
  имя обновляются автоматически. Если кто-то удалил username, жеребьёвка
  откладывается, регистрация остаётся открытой, в группе показывается, кому
  нужно обновить данные.
- **Пожелание фиксируется в момент жеребьёвки** и хранится в назначении,
  поэтому `/retry` отправляет ровно то же сообщение.
- **Заблокировал бота.** Остальные получают сообщения; в группе видно, кому не
  доставлено. После разблокировки достаточно нажать Start в личке — назначение
  придёт автоматически; организатор также может отправить `/retry`.
- **Группа стала супергруппой** — ID группы в играх обновляется.

## Тесты

```bash
pip install -r requirements-dev.txt
python -m pytest
```

Покрыто: жеребьёвка для 2, 3, 5 и более участников; повторный Start; пользователь
без username; замена пожелания и выбор группы; приватность пожеланий;
параллельный двойной `/end`; регистрация после жеребьёвки; блокировка бота и
повторная доставка исходного назначения; сквозной сценарий через `Dispatcher`
с имитацией Bot API.
